## LinkedIn

Today I’m launching **isWebMCP** — an evidence lab for a web that AI agents can use without guessing.

Most “agent-ready” claims collapse very different signals into one score. A semantic form is not a tool contract. A tool contract is not a successful runtime trial. And a successful trial is not proof that the tool path improved on the UI.

isWebMCP keeps those layers separate:

- Scan bounded public source and map candidate actions
- Lint sanitized WebMCP contracts
- Explore 24 interactive before-and-after patterns
- Run one synthetic task through UI and tool paths
- Publish raw verification evidence before calculating lift

We also show the integrity failure in our own WRI v1 crawl instead of hiding it. The artifact is labeled audited-partial and uncalibrated, with scanner-infrastructure failures quarantined rather than attributed to websites.

WebMCP is experimental Community Group work. isWebMCP is independent and free to use.

I’d love a rigorous answer to this: what evidence would make you trust that your web app is agent-ready?

https://iswebmcp.com

## Hacker News — Show HN

**Title**

Show HN: isWebMCP – evidence for agent-ready web apps

**Text**

I built isWebMCP to test a narrower claim than “this site has WebMCP”: can an agent complete a defined task safely, verify the postconditions, and show an observable improvement over the visible UI path?

The app has four deliberately separate evidence layers: a bounded public-source scan, sanitized contract lint, observed runtime trials, and matched UI-versus-tool lift. It also includes a synthetic Proof Lab and 24 explorable interaction patterns.

The source scanner does not execute target JavaScript, imported definitions are not treated as independently verified, and numeric lift is withheld unless both runs are interactive and comparable.

One thing I expect HN to scrutinize is the public readiness index. WRI v1 scheduled 100,000 ranks, but an audit found two scanner-wide failure windows. We froze it as an uncalibrated audited-partial artifact: 65,380 valid collection outcomes, 34,620 quarantined infrastructure errors, and 36,323 scored rows. It is not a definitive website ranking.

WebMCP is experimental Community Group work. The project is independent and free: https://iswebmcp.com

I’d appreciate criticism of the evidence model, especially what should qualify as a comparable runtime trial.

## Indie Hackers

**Title**

I turned a flawed 100k-row crawl into the trust model for my launch

**Post**

I’m launching isWebMCP, a free evidence lab for agent-ready web apps.

The first version leaned too hard on a confident readiness score. During an integrity review, we found two scanner-wide failure windows in a 100,000-rank collection. Instead of smoothing over the data, we froze the artifact, quarantined 34,620 infrastructure errors, labeled the heuristic uncalibrated, and rebuilt the product around evidence provenance.

Now a source hint cannot masquerade as runtime success. An imported schema cannot become certification. A synthetic replay cannot produce measured lift. The product shows what is known, how it was observed, and what remains unknown.

That redesign produced a much better product: a bounded URL scan, contract workbench, matched-path Proof Lab, 24 interactive patterns, learning center, and a public audited-partial dataset.

I’d love feedback from builders: does the evidence ladder make the value immediately legible, and where would you still hesitate to trust it?

## Reddit/community post

**Title**

I built an evidence lab for testing whether a web app is actually agent-ready

**Body**

I’ve been working on isWebMCP, a free tool for separating four claims that often get mixed together: source-level actionability, contract quality, observed runtime success, and measured improvement over the human UI path.

It includes a bounded public URL scan, sanitized contract lint, a synthetic Proof Lab that runs the same task through two paths, and 24 interactive patterns across value, security, reliability, and contract design.

Important limitations are visible in the product: the public scan does not execute target JavaScript; imported contracts are not independently verified; runtime metrics require observed trials; and the public WRI v1 dataset is explicitly frozen, uncalibrated, and audited-partial after scanner failures were found.

WebMCP is experimental Community Group work, and this is an independent project.

If this is relevant to your community’s rules, I’d value technical criticism: what would you require before accepting an “agent-ready” claim?
