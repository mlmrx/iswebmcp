# Demo script — 160 seconds

Target length: 2:40 with narration and audio. Use one clean browser window, 125–150% cursor visibility, and no personal tabs or notifications.

## 0–15 seconds — The problem

**Screen:** Hero, Quick Scan, and “Presence is not proof.”

**Narration:** “A site can mention WebMCP—or even register tools—and still be unusable by an agent. Presence is not readiness, and readiness is not successful, safe action. isWebMCP turns that gap into evidence.”

## 15–42 seconds — Detect without pretending

**Screen:** Submit a prepared public URL and open the report.

**Narration:** “Quick Scan safely reads public source without executing the target’s JavaScript. It maps semantic controls, accessible names, actions, transport, and source hints. Every conclusion shows its provenance, while runtime remains explicitly unverified.”

Pause on the three measurement cards.

**Narration:** “Baseline Actionability, WebMCP Implementation Quality, and WebMCP Lift stay separate. Unknown evidence never becomes a made-up zero—or a made-up success.”

## 42–65 seconds — Audit the contract

**Screen:** Import the bundled sanitized manifest example, then reveal the derived report and one finding.

**Narration:** “A developer can import a sanitized tool inventory. isWebMCP bounds and summarizes the schema, rejects credential-like or dangerous structure, and creates an immutable derived report. Imported evidence is always labeled not independently verified.”

## 65–92 seconds — The same human task

**Screen:** Proof Lab in baseline mode. Show filters, compare, cart, and deterministic criteria; use controlled baseline replay or the prepared completed baseline.

**Narration:** “The proof lab uses one synthetic catalog, one visible interface, one business-logic path, and seven observable success criteria. The baseline records committed UI actions for the headset-selection task.”

## 92–127 seconds — WebMCP completes it

**Screen:** Switch to WebMCP mode. Show the agent/tool trace for search, compare, cart, and finish while visible state updates.

**Narration:** “In WebMCP mode, the same page adds narrow top-level tools. Structured search filters the visible catalog. Compare uses stable IDs. Cart updates the same UI state. Finish verifies every postcondition, and the lab never performs checkout.”

## 127–146 seconds — Prove the difference

**Screen:** WebMCP Lift comparison.

**Narration:** “Only comparable, completed runs produce WebMCP Lift. The report publishes raw actions, time, retries, intervention, verification, each normalized component, and the formula. A bad implementation is allowed to score worse.”

## 146–160 seconds — Leverage and close

**Screen:** Methodology tool grid, then return to hero.

**Narration:** “isWebMCP itself exposes twelve validated, lifecycle-clean tools while remaining fully useful without them. It helps the web move from tools detected to agent action proven. Detect it. Test it. Prove it.”

## Capture notes

- Keep the deployment URL visible once.
- Show “source-only,” “not independently verified,” and “controlled replay” labels long enough to read.
- Use a supported browser/model and preserve the real tool trace—do not animate fake calls.
- Record at 1080p or higher, normalize narration audio, add captions, and verify the final exported video is under three minutes.
